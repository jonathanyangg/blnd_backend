Create two new files:

**ImportModels.swift** (`blnd_ios/blnd_ios/Models/ImportModels.swift`):
- `struct ImportSummaryResponse: Decodable` with fields: `imported: Int`, `skipped: Int`, `failed: Int`, `failedTitles: [String]`
- `CodingKeys` enum mapping `failedTitles` to `"failed_titles"` (snake_case backend convention)

**ImportAPI.swift** (`blnd_ios/blnd_ios/Networking/ImportAPI.swift`):
- `enum ImportAPI` with a single static async throwing function: `static func upload(zipData: Data) async throws -> ImportSummaryResponse`
- Build a `URLRequest` from scratch (do NOT use `APIClient` — it always sets `Content-Type: application/json` which would break multipart). Mirror the `AvatarUploader` pattern of direct URLSession usage.
- URL: `APIConfig.baseURL + "/import/letterboxd"`
- Method: POST
- Headers: `Content-Type: multipart/form-data; boundary=\(boundary)` where boundary is `UUID().uuidString`
- Auth: Read token via `KeychainManager.readString(key: "accessToken")`, set `Authorization: Bearer \(token)`. If no token, throw `APIError.unauthorized`.
- Body construction (RFC 7578 multipart/form-data — use `\r\n` CRLF everywhere, not `\n`):
  - `--{boundary}\r\n`
  - `Content-Disposition: form-data; name="file"; filename="export.zip"\r\n`
  - `Content-Type: application/zip\r\n\r\n`
  - append zipData bytes
  - `\r\n--{boundary}--\r\n`
- Send via `URLSession.shared.data(for: request)`
- Guard response is `HTTPURLResponse` with status 200..<300, else throw `APIError.serverError(statusCode)`
- Decode response data to `ImportSummaryResponse` via `JSONDecoder()`
- Use `///` doc comment on the upload function

Both files: `import Foundation` only. Follow existing naming conventions (PascalCase files, camelCase properties, CodingKeys for snake_case mapping).

```swift
private enum ImportViewState {
    case instructions
    case loading
    case results(ImportSummaryResponse)
    case error(String)
}
```

**State properties:**
- `@State private var viewState: ImportViewState = .instructions`
- Keep existing: `@State private var showWebView = false` and `@State private var capturedZipData: Data?`
- Add: `@State private var uploadTask: Task<Void, Never>?`
- Add: `@Environment(\.dismiss) private var dismiss`

**Body structure:**
```swift
var body: some View {
    Group {
        switch viewState {
        case .instructions:
            instructionsContent
        case .loading:
            loadingContent
        case let .results(summary):
            resultsContent(summary: summary)
        case let .error(message):
            errorContent(message: message)
        }
    }
    .animation(.easeInOut(duration: 0.3), value: stateKey)
    // ... fullScreenCover and onChange modifiers
}
```

Add a computed `stateKey` (String) property that returns a unique key per state case (e.g., "instructions", "loading", "results", "error") to drive the animation value.

**Instructions state** (`instructionsContent`):
- Preserve existing layout exactly: ScrollView with brandingHeader + instructionsCard + Spacer, then AppButton "Continue" at bottom
- Keep existing fullScreenCover modifier for LetterboxdWebView
- Background: AppTheme.background

- `.onChange(of: capturedZipData)` modifier with two-argument form `{ oldValue, newValue in ... }`
- Guard: `oldValue == nil && newValue != nil` (only trigger on nil -> Data transition, per Pitfall 4)
- On trigger: call `startUpload()` private function

**`startUpload()` function:**
- Set `viewState = .loading` (wrap in `withAnimation`)
- Create a new `Task` and store in `uploadTask`:

  - `do { let summary = try await ImportAPI.upload(zipData: zipData); withAnimation { viewState = .results(summary) } }`
  - `catch { if !(error is CancellationError) { withAnimation { viewState = .error("Something went wrong. Please try again.") } } }`
  - Log raw error to console: `print("[Import] Upload failed: \(error)")`

**`.onDisappear` modifier:**
