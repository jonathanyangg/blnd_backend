    Add two private helper functions to `workflows.py`:

    **`_title_matches(lb_title: str, tmdb_title: str) -> bool`:**
    - Strip punctuation from both titles, lowercase, split into word sets
    - Remove stopwords: `{"the", "a", "an", "of", "in", "to", "and", "or"}`
    - If Letterboxd word set is empty after stopword removal, return `True` (degenerate case — accept match)
    - Return `True` if the two word sets share at least one word (set intersection is non-empty)
    - Use `re.sub(r"[^\w\s]", "", title.lower()).split()` for word extraction

    **`async def _resolve_tmdb_id(name: str, year: int | None, tmdb_client: httpx.AsyncClient) -> int | None`:**
    - Build params dict: `{"query": name}`
    - If `year` is not None, add `"primary_release_year": str(year)` (per research: use `primary_release_year` not `year`)
    - Call `response = await tmdb_client.get("/search/movie", params=params)`
    - Call `response.raise_for_status()`
    - Get `results = response.json().get("results", [])`
    - If no results, return `None`
    - Take first result: `top = results[0]`
    - Call `_title_matches(name, top.get("title", ""))` — if `False`, return `None`
    - Return `top["id"]`

    Add `import re` to the imports at the top of the file.

    **New imports to add:**
    - `from app.tracking.models import WatchedMovie, WatchlistMovie`
    - `from app.movies.services import get_movie_details`

    **Processing loop in `run_letterboxd_import()`** — iterate over `merged.items()`:

    For each `(uri, record)` in the merged dict, wrap the entire per-movie block in `try/except Exception`:

    1. **Resolve TMDB ID:** `tmdb_id = await _resolve_tmdb_id(record.name, record.year, tmdb_client)`. If `None`, append `record.name` to `failed_titles`, increment `failed`, `continue`.

    2. **Cache movie via existing service:** `await get_movie_details(tmdb_id, db, tmdb_client)` — this fetches full TMDB detail and commits to movies table if not already cached (TMDB-02). Accept that `get_movie_details` calls `db.commit()` internally per movie (per research Pitfall 1, this is acceptable).

    3. **Handle watched entry (IMPT-01, IMPT-02, IMPT-03):**
       - If `record.in_watched` OR `record.liked` (liked-but-not-watched creates a watched entry too):
         - Query-first duplicate check: `existing = db.query(WatchedMovie).filter(WatchedMovie.user_id == user_id, WatchedMovie.tmdb_id == tmdb_id).first()`
         - If `existing`:
           - If `record.liked and not existing.liked`: update `existing.liked = True`, call `db.commit()` (set liked flag on pre-existing entry per IMPT-03)
           - Increment `skipped`
         - Else (no existing entry):
           - Create `WatchedMovie(user_id=user_id, tmdb_id=tmdb_id, rating=record.rating, review=record.review, watched_date=record.watched_date, liked=record.liked)`
           - `db.add(entry)`, `db.commit()`
           - Increment `imported`

    4. **Handle watchlist entry (IMPT-04):**
       - If `record.in_watchlist`:
         - Query-first duplicate check: `existing_wl = db.query(WatchlistMovie).filter(WatchlistMovie.user_id == user_id, WatchlistMovie.tmdb_id == tmdb_id).first()`
         - If `existing_wl`: skip (already counted in watched handling or just skip silently)
         - Else: Create `WatchlistMovie(user_id=user_id, tmdb_id=tmdb_id, added_date=record.watchlist_date)`, `db.add(entry)`, `db.commit()`, increment `imported`

    5. **Exception handler (IMPT-05):** In the `except Exception` block:
       - `logger.warning("Failed to import %s (%s)", record.name, record.year, exc_info=True)`
       - Append `record.name` to `failed_titles`
       - Increment `failed`
       - `continue` the loop

    **After the loop:** Return `{"imported": imported, "skipped": skipped, "failed": failed, "failed_titles": failed_titles}`.

    **Important details:**
    - For liked-but-not-watched films (record.liked is True but record.in_watched is False): the watched entry should have `rating=None`, `review=None`, `watched_date=None`, `liked=True` — the FilmRecord already has these as None since only likes/films.csv set the liked flag without setting other fields (per CONTEXT.md decision).
    - Use the project's query-first pattern (not IntegrityError catch) per research anti-patterns.
    - Do NOT use `record.rating` for films that are only liked (not in ratings.csv / watched.csv) — the FilmRecord correctly has `None` for those fields already from the merge step.
