1. **Content-Length header check (pre-read):** Add `content_length: int = Header(default=0, le=MAX_UPLOAD_SIZE)` parameter to the endpoint signature. Define `MAX_UPLOAD_SIZE = 10 * 1024 * 1024` (10 MB) as a module-level constant. Use `default=0` (not required) per research Pitfall 2 -- some clients may omit Content-Length with chunked encoding. FastAPI returns 422 automatically if the header exceeds the limit.

2. **Post-read byte length check:** After `file_bytes = await file.read()`, check `if len(file_bytes) > MAX_UPLOAD_SIZE:` and raise `HTTPException(status_code=413, detail="File too large (max 10 MB)")`. This catches spoofed Content-Length headers.

3. **Zip format + decompression ratio validation:** Create a helper function `_validate_zip(file_bytes: bytes) -> None` in `views.py` that:
   - Checks `zipfile.is_zipfile(io.BytesIO(file_bytes))` -- if not, raise `HTTPException(status_code=400, detail="File is not a valid zip archive")`
   - Opens the zip and checks decompression ratio: `sum(info.file_size for info in zf.infolist()) / len(file_bytes) > MAX_DECOMPRESSION_RATIO` (define `MAX_DECOMPRESSION_RATIO = 100` as module-level constant) -- if exceeded, raise `HTTPException(status_code=400, detail="Zip archive failed validation")`

Call `_validate_zip(file_bytes)` after the size check, before `workflows.run_letterboxd_import(...)`.

Add imports: `import io`, `import zipfile`, `from fastapi import Header, HTTPException`. Note: `HTTPException` may need to be added to the existing fastapi import line.

Do NOT use `file.content_type` for validation (client-spoofable per research anti-patterns). Use fixed, generic error messages -- do NOT include raw exception details in HTTP responses (research Pitfall 5).

Keep the existing `_run_seed_pipeline_sync` function and `seed_movies` endpoint unchanged.
